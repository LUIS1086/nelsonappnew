# v3.9.15 — Fluidez al abrir la app
- La pantalla de bienvenida (splash) antes esperaba 1800 ms fijos antes de mostrar el PIN; ahora 1100 ms (`SPLASH_MS` en `js/modules/21-config-acciones-seguridad.js`; poner 1800 para volver al valor anterior). No se quitó ni cambió ninguna función.
- **html2canvas bajo demanda:** ya no se carga al abrir la app (199 KB menos que descargar y procesar en cada arranque). `index.html` define una función puente `html2canvas` con la misma firma; la primera vez que se usa (tickets, QR, diagnóstico, órdenes) descarga la librería real desde la caché del service worker y la reemplaza. Además se precarga sola en segundo plano cuando el teléfono está libre (tras abrir la app), así que normalmente ya está lista al usarla y no hay espera. Los 6 sitios que la llaman no se modificaron (todos esperan su resultado). Si falla la carga, se mantiene el mensaje "html2canvas no disponible".
- Revisión sin cambios necesarios: los 6 archivos de `js/libs/` se usan; los iconos PNG ya están optimizados; el CSS en línea de `index.html` (facturas) no está duplicado en el bundle; las caches y el service worker están bien configurados.
- **Calidad automática:** nuevo `.github/workflows/verificar.yml`: en cada subida a GitHub corre `tools/verificar.js` con ESLint, para detectar errores como el del dashboard (v3.9.12) antes de que lleguen a Vercel. Nuevo `.editorconfig` para mantener el mismo formato (UTF-8, 4 espacios, LF) en cualquier editor.
